A module is a folder of plain files that gives your assistant one new job: how to run your weekly review, how to keep a reading log, how to quiz you before a test. They install into your own brain folder, so they're yours to read, edit, and throw away.

Make one

The fastest way to write one is to ask for it

Say what it should do

Your assistant writes modules. Describe the job in a sentence and it scaffolds the folder, writes the instructions, and puts it straight into your brain where it works immediately.

"make me a module that tracks my runs"

Use it, then fix it

It's live in the next tab you open. When it gets something wrong, say so and the instructions get edited. That's the whole loop, and there's nothing to compile.

"the run log should record how it felt too"

Share it if you want

A module is a folder. Put it in a public repo, open a pull request adding one line to the registry, and an automatic check reads it before a person does. Or keep it to yourself. Both are fine.

"help me publish the run tracker"
How to write one

Two things worth knowing

A module is somebody else's work, running in your folder

It can read and change anything in the brain you install it into, and some of them ship scripts that run on your Mac. Every card here says which, and your assistant reads it back to you and waits for a yes before writing a single file. Those labels are read out of each module's own files rather than taken from what its author says about it, so they can be wrong in both directions. The source is one click away. Read it like you'd read a script a stranger sent you.

This is a list, not a review

Nothing here has been audited for safety. A submission gets an automatic check and a read-through by one person, which catches carelessness and not much else. Listing is not endorsement. Anything can come off the list, and getting one out of your own brain is just asking for it gone. The folder lands in your Trash, not nowhere.
